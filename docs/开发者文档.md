# 开发者文档

> 面向要改这个项目的人：目录怎么分、代码怎么分层、改一处会牵动哪里、怎么验证。
> 玩家向的功能说明在根目录 `README.md`；模组作者看 [模组开发指南.md](模组开发指南.md)。
> 本文件与《模组开发指南》会随仓库发布；其余 `docs/` 下的文件是开发过程笔记，不进版本库。

---

## 1. 仓库结构

```
BlastPioneer/
├── src/                     程序本体（只有代码）
│   ├── game/                引擎：纯 QtCore，可脱机测试
│   ├── core/                单例与服务（目录/文件/设置/存档/数据库/网络/主题/崩溃保护）
│   ├── ui/                  界面框架（窗口壳、页面骨架、路由、自绘控件）
│   ├── screens/             14 个界面（每个一个 .h/.cpp）
│   ├── main.cpp             入口：命令行、目录解析、界面注册、自检/截图模式
│   ├── version.h            版本号唯一来源
│   ├── Resource.qrc         打包进二进制的兜底资源（用 alias 保持 :/Data/... 路径）
│   └── startupEffect.qml    启动特效（唯一的 QML，走 QQuickWidget）
├── content/                 随程序发布的内容（改这些不用编译）
│   ├── Data/                gameplay 默认值、items、levels/*.json、mod_api.json、规则文本
│   ├── Assets/picture/      图片
│   ├── ui/                  主题（tokens.json + light.qss + dark.qss）
│   └── mods/                随仓库发布的示例模组（默认不启用）
├── sdk/                     原生模组 SDK（C 头文件、Python 声明、载入器、示例）
├── tools/                   package_release.ps1 / make_manifest.ps1 / test_updater.ps1 / updater/
├── tests/                   引擎测试（qmake 影子构建到 build/tests）
├── build/                   构建产物（不进版本库）
└── BlastPioneer.vcxproj     BlastPioneer.slnx（包含主程序与更新器两个工程）
```

**两条硬约定**（破坏它们后面的人会很痛苦）：

1. `src/` 只放代码，`content/` 只放内容。运行期 `content/` 下的四个目录会被**平级**复制到 exe 旁边
   （`Assets/` `Data/` `ui/` `mods/`），所以代码里的路径永远是 `Data/...`、`ui/...`，
   由 `BlastPioneer.vcxproj` 的 `CopyContentToOutDir` 目标负责映射。
2. 颜色 / 字号 / 圆角只写在 `content/ui/*.qss`，控件里只 `setObjectName`。
   **没有 qss 规则的控件会吃系统调色板的颜色** —— 玩家开深色模式时就是浅字压浅底（真实事故）。

## 2. 分层与数据流

```
main.cpp
  └─ AppHost（窗口 + 全局按键过滤） ── ScreenRouter（栈式路由）
        └─ screens/*Screen（页面骨架 ScaffoldScreen：标题/内容/底部按钮）
              └─ core/* 单例（数据与状态）
                    └─ game/*（引擎：规则与状态机）
```

- **引擎（`src/game/`）** 不知道界面存在。它接收"输入意图"，产出 `GameSnapshot`（渲染用只读快照）
  与事件队列（`GameEvent`）。`SingleGameEngine` / `MultiGameEngine` 只差"谁是权威"。
- **界面** 每帧读快照画图（`GameCanvas`），不直接持有引擎内部结构。
- **core/** 的每个单例都从 `DirectoryLayout` 取路径（`root()`、`dataDir()`…），
  所以 `--root=<目录>` 能把整个数据目录搬走（调试与隔离测试都靠它）。
- **主题** 由 `ThemeManager` 统一：令牌替换 → 主题 qss → 模组追加的 override.qss。

### 启动管线

`SplashScreen` 起一个工作线程跑 `BootstrapTask` 的 7 步（检查目录 → 设置 → 存档 → 模组 → 道具 →
关卡 → 图片），完成后 `markReachedHome()`，再由 `ScreenRouter` 决定进主页还是欢迎页。
崩溃保护（`LaunchGuard`）靠 `Data/launch_state.json` 记录"正在加载哪个模组/是否到过主页"。

> ⚠️ 因此界面是**预创建**的：构造函数跑在数据加载**之前**。构造里只搭结构，
> 内容一律在 `onEnter` 里填。踩过的坑：主页金币/经验一直显示 0。

## 3. 扩展点速查

| 要改的东西 | 动哪里 | 注意 |
|---|---|---|
| 玩法数值 / 道具 / 关卡 | `content/Data/*.json` | 不用编译；`levels/` 加文件即可加关卡 |
| 界面配色 / 加主题 | `content/ui/tokens.json` + `*.qss` | 控件必须有 objectName 规则 |
| 加一个界面 | `src/screens/` + `main.cpp` 的 `registerScreen` + `ScreenId` | 内容在 `onEnter` 里填 |
| 游戏画面 / HUD | `src/ui/GameCanvas.*`、`GameHud.*` | 只读快照，不改引擎状态 |
| 引擎规则 | `src/game/GameEngine.*` 及子类 | 改完必须跑 `tests/run_tests.bat` |
| 模组能力（ABI） | `sdk/bp_mod_api.h` 末尾追加 | 见第 5 节；同步引擎侧与 Python 声明 |
| 打包内容 | `tools/package_release.ps1` | 白名单；改完必须让打包自检通过 |
| 更新器行为 | `tools/updater/main.cpp` | 见第 6 节的三条硬规矩 |

## 4. 构建与验证

```powershell
# 环境（只在这台机器上需要设一次；也能写进仓根 qt-env.bat，已 gitignore）
$env:QTDIR = "C:\Qt\6.10.2\msvc2022_64"

msbuild BlastPioneer.vcxproj        /p:Configuration=Release /p:Platform=x64
msbuild tools\updater\Updater.vcxproj /p:Configuration=Release /p:Platform=x64

cd tests ; .\run_tests.bat                          # 引擎测试（qmake 影子构建）
.\build\Release\BlastPioneer.exe --ui-selftest       # 14 个界面构造一遍
.\build\Release\BlastPioneer.exe --ui-shot=<目录>    # 每屏截图（改配色/布局后自查）
pwsh -File tools\package_release.ps1                 # 出包（白名单 + 干净化 + 启动自检）
pwsh -File tools\test_updater.ps1                    # 更新器端到端（本地 HTTP，不联网）
```

**"改完了"的判定**：上面五条里，前四条必须全绿；动了打包/更新器就再跑后两条。
当前基线：引擎测试 `passed 519, failed 0`、跨语言 ABI 55 项、Python 载入器 22 项、更新器 0 失败。

测试代码在 `tests/test_game_core.cpp`：一个 `CHECK` 宏 + 分组函数，**断言信息必须是 ASCII**
（宏内部走 `printf`，中文在部分终端会乱码）。新增行为请顺手加一组断言。

## 5. 模组 ABI 的三条铁律

1. **只能末尾追加**：结构体加字段、函数表加指针都只能加在最后；
   `BpHostApi` 里 0.1.0 就留下的 `reserved_*` 槽位可以"就地填成真函数"（布局不变），
   0.1.2 就是这么把 `reserved_mode` 变成 `register_mode` 的。
2. **偏移量有编译期保险**：`bp_mod_api.h` 末尾的 `static_assert` 钉住 0.1.0 承诺过的偏移，
   `tests/test_game_core.cpp` 里还有一组运行期断言。改布局会直接编译失败 —— 那是好事。
3. **改能力要三处同步**：`sdk/bp_mod_api.h`（C）、`sdk/python/bp_mod_api.py`（Python 声明）、
   `Data/mod_api.json`（版本与能力声明）；接口版本号在 `BP_MOD_API_VERSION`，ABI 版本在
   `BP_MOD_ABI_VERSION`（只有破坏性改动才 +1）。

宿主侧实现在 `src/core/NativeModHost.cpp`：`hp_*` 是函数表里的静态回调，
`registerModeForCurrentMod` / `generateModeMap` / `onModEnemyThink` / `onModCheckWin` 是钩子适配层。
**所有写请求必须过引擎校验**（越界/墙/上限/已结束 → `BP_ERR_REJECTED`），
这是"模组不能破坏游戏"的唯一保证点。

## 6. 更新器

独立 `Updater.exe`（Qt C++，不用 moc），与主程序共用同一套 Qt DLL。清单格式：

```json
{ "schema": 1, "version": "0.1.1", "channel": "stable",
  "publishedAt": "...", "minUpdater": "0.1.0",
  "files": [ { "path": "Data/ui/light.qss", "size": 18211, "sha256": "…" } ],
  "delete": [ "old/removed.txt" ] }
```

三条硬规矩（比功能重要）：

1. **只动包内路径**：拒绝绝对路径、`..`、盘符；
2. **用户数据永不触碰**：存档 / 设置 / 崩溃记录 / `logs/` / `cache/` / `mods/` / `Update/`
   即使出现在清单里也拒绝；
3. **校验不过就整体中止**：先下到 `Update/staging/` 逐文件校验 sha256，再备份 → 替换 → 自检，
   自检失败全量回滚。`version.txt` 只在自检通过后才写。

更新源是**有序列表**（默认 jsDelivr → ghfast → GitHub raw），设置页可关掉镜像、可勾选追踪预发布版。
版本比较按语义化版本处理：`0.1.0-beta.1 < 0.1.0-beta.2 < 0.1.0-rc.1 < 0.1.0`。

## 7. 代码风格与本仓库的几条习惯

- 注释写**为什么**（尤其"为什么不能那样写"），不写"这行在做什么"。中文注释可以直接写。
- 源文件编码 UTF-8；`.bat` 与 `.ps1` 必须注意编码：`.bat` 只能 ASCII，
  `.ps1` 若含中文必须存成 **UTF-8 with BOM**（PowerShell 5.1 否则按 ANSI 读，引号会被吃掉）。
- 界面层禁止 `setStyleSheet`（除 `ThemeManager`），颜色一律进 qss。
- 提交前看 `git status --short`：`build/`、`dist/`、`docs/`（除本文件与模组指南）、`*.dll` 都不该出现。
