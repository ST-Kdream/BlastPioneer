# 模组开发指南

一个模组 = `mods/` 下的一个文件夹。放进文件夹、在游戏里勾一下就能生效，
**不需要重新编译，也不需要改游戏本体的任何文件**。

- 想改**界面配色**？→ 第 4 节
- 想改**玩法数值**？→ 第 3 节 + 第 6 节的白名单
- 想**加关卡**？→ 第 3 节 + `content/Data/levels/level_01.json`（结构自解释）
- 想用 **C/C++/Rust/C#/Go/Python 写原生模组**（DLL，能订阅事件、读写世界）？→ 第 9 节
- 想知道**什么算破坏性改动**？→ 第 5 节
- 游戏**打不开了**（原生模组崩了）？→ 第 9.5 节：安全模式

## 1. 目录结构

```
<exe 旁边>/
├── Data/mod_api.json           本构建的兼容性声明（你不用改，但要知道它存在）
└── mods/
    └── <你的模组 id>/
        ├── mod.json            必须：自我声明
        ├── config/             可选：写几份都行
        │   ├── gameplay.json   玩法数值
        │   ├── items.json      道具字段
        │   ├── levels.json     关卡覆盖 / 新增
        │   └── ui.json         界面令牌（配色、圆角、间距）
        └── ui/
            └── override.qss    可选：追加的样式表
```

游戏里「主页 → 模组」有「打开模组文件夹」按钮可以直接跳到这个目录。

## 2. `mod.json`

```json
{
  "id": "my_first_mod",
  "name": "我的第一个模组",
  "version": "1.0",
  "author": "你的名字",
  "description": "一句话说明这个模组做什么",
  "apiVersion": 1,
  "priority": 0,
  "enabledByDefault": false,
  "features": ["gameplay", "items", "levels", "ui"]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 建议 | 唯一标识；没写时用目录名兜底 |
| `name` | 否 | 显示名；没写时用 `id` |
| `version` | 否 | 你自己的版本号（字符串，随便写） |
| `author` / `description` | 否 | 显示在模组的详情里 |
| `apiVersion` | **必须** | 你按哪一版接口写的。**没写会被拒绝加载** |
| `priority` | 否 | 默认 0。多个模组改同一个键时，**数值大的覆盖小的** |
| `enabledByDefault` | 否 | 默认 `true`。玩家第一次运行时是否默认启用 |
| `features` | 否 | 你用到了哪些能力。留空会按你实际放了哪些文件自动推断，但**显式声明更安全**：声明了本版本没开放的能力会被明确拒绝，而不是"加载了却没反应" |
| `native` | 否 | `true` = 这是个**原生模组**（带 DLL，见第 9 节）。默认 `false` |
| `nativeLib` | 否 | DLL 文件名（不带扩展名）。留空 = 用 `id` |

能力名：`gameplay`（玩法数值）、`items`（道具）、`levels`（关卡）、`ui`（界面外观）、
`hooks`（原生模组，见第 9 节）。`modes`（全新模式）**尚未开放**，声明了会被拒绝加载。

> **`apiVersion` 写老版本也能用**：本构建接受 `0.1.0` 与 `0.1.1`。
> 接口只会"末尾追加"，所以按 `0.1.0` 写的模组在 `0.1.1` 的引擎上照常加载 ——
> 这正是版本号只在**破坏性**改动时才进位的原因。

## 3. 三份数据覆盖：只写差异

三份文件都是**补丁**，不是替换：**没写的字段保持原值**。
所以引擎以后新增数值时会自动跟上，你的模组不会因为"少写一个字段"而变旧。

**`config/gameplay.json`** —— 键名见第 6 节白名单：

```json
{
  "playerSpeed": 4.2,
  "playerBombRange": 2,
  "dropChance": 0.5,
  "multiSelfDamage": true
}
```

**`config/items.json`** —— 键 = 道具名，值是"要改的字段"：

```json
{
  "生命药水": { "price": 10, "dropWeight": 60 },
  "示例护符": {
    "description": "模组新增的道具",
    "price": 1,
    "iconPath": "Assets/picture/liveBottle.png",
    "effect": "heal",
    "dropWeight": 5
  }
}
```

- 道具**已存在** → 按字段覆盖；道具名**不存在** → 新增一件道具（直接出现在商店与背包里）；
- `effect` 只能用引擎已经实现的效果 id（例如 `heal`、`speed_up`、`bomb_range_up`、`bomb_capacity_up`）；
  写了一个没实现的效果，道具会正常出现，但使用时没有任何效果 —— 日志里会记一条。

**`config/levels.json`** —— 键 = 关卡号：

```json
{
  "1": { "name": "改过的第一关", "bricks": 12, "coins": 200 },
  "99": { "name": "模组新增的关卡", "enemyCount": 2, "enemyHp": 1, "seed": 9901 }
}
```

- 关卡号**已存在** → 按字段覆盖（只写 `bricks` 就只改砖块数，地图布局还是原来的）；
- 关卡号**不存在** → 新增一关，会出现在关卡选择里。

字段表与手绘地图的字符表见 `content/Data/levels/level_01.json`（结构自解释）。

## 4. 界面外观

**换配色（推荐先试这个）** —— `config/ui.json`，键名就是界面令牌：

```json
{
  "primary": "#7B2FF7",
  "primaryHi": "#9B5CFF",
  "accent": "#FF7A18",
  "radius": "2px",
  "gap": "10px"
}
```

全部可用令牌名与它们的作用在 `ui/tokens.json`（浅色与深色主题共用同一批名字）。
**只改一组颜色就能整体换肤**，不用管每个界面有哪些控件。

**改某个控件的长相** —— `ui/override.qss`，会在主题样式表之后追加：

```css
#startBtn { background-color: #7B2FF7; border-radius: 2px; }
#hudValue { color: #FFD54F; }
```

- **只能追加，不需要替换**：Qt 的 QSS 是"同优先级下后写的胜出"，所以写你关心的那几条就够，
  主题升级时你也不会被迫跟着改；
- **这里也能用令牌**：写 `@primary` 会和你 `config/ui.json` 里的覆盖一起生效；
- 可用的控件 id 清单见 `content/ui/light.qss` 的选择器（以及 `src/screens/` 里对应的 `setObjectName`） 第 3 节。

**安全约定**：令牌名拼错或类型不对 → 忽略那一条并在日志里点名；
关掉模组 → 立刻恢复原样（每次应用主题时重算，不会残留）。

## 5. 兼容性

游戏启动时读 `Data/mod_api.json`，拿它和你 `mod.json` 里的 `apiVersion` / `features` 比对：

| 你的声明 | 结果 |
|---|---|
| 没写 `apiVersion` | ❌ 拒绝：「缺少 apiVersion」 |
| `apiVersion` 不在支持列表里 | ❌ 拒绝：「本版本不支持 mod 接口 vX（本版本支持：0.1.0、0.1.1）」 |
| 声明了本版本标成 `false` 的能力 | ❌ 拒绝：「需要「modes」能力，本版本尚未开放」 |
| 声明了不认识的能力名 | ❌ 拒绝：「声明了未知能力「xxx」」（防拼错） |
| 以上都通过 | ✅ 加载 |

**什么时候版本号会 +1（破坏性改动）**：删字段、改字段含义、改键名、把某个能力标成 `false`、
**重命名或删除**已有的令牌名 / 控件 id、改样式表的叠加顺序、
改 C ABI 里**既有**的函数签名或字段含义。

**什么时候不变**（你的老模组继续能用）：追加字段、新增可覆盖的键、新增能力位、
新增令牌名或新控件 id、**在 C ABI 函数表/结构体末尾追加**。

## 6. `gameplay.json` 可改的键

键名写错**不会静默生效**：会被忽略并记一条"未知的玩法键「xxx」，已忽略"。

| 分类 | 键名 | 单位 / 说明 |
|---|---|---|
| 玩家 | `playerSpeed` | 格/秒 |
| | `playerMaxLives` | 初始生命上限 |
| | `playerBombRange` | 爆炸威力（向四个方向各延伸几格） |
| | `playerMaxBombs` | 同时可放的炸弹数 |
| | `playerBombFuse` | 玩家炸弹引信（秒） |
| 敌人 | `enemySpeed` | 格/秒 |
| | `enemyBombFuse` | 敌人炸弹引信（秒） |
| | `enemyBombRange` | 敌人炸弹威力 |
| | `enemyBombCooldown` | 放弹冷却（秒） |
| | `enemyBombsPerSecond` | 每秒期望放弹次数 |
| | `enemyTurnChancePerSecond` | 每秒期望主动换向次数 |
| | `enemyReversePenalty` | 掉头权重倍率（越低越不回头） |
| | `enemyRetryProbeCount` | 撞墙后的试探次数 |
| 地图 | `brickBaseCount` / `brickPerLevel` | 砖块数 = base + perLevel × 关卡 |
| | `enemyCountPerLevel` | 敌人数 = 关卡 × 该值 |
| | `enemyHpBase` / `enemyHpLevelDiv` | 敌人血 = base + 关卡 / div |
| 掉落与提示 | `dropChance` | 砖块被炸后掉道具的概率 |
| | `explosionPersistSeconds` | 爆炸痕存续（秒） |
| | `dropLifetimeSeconds` | 掉落物存在时长（0 = 永久） |
| | `warningSeconds` | 爆炸前多少秒开始闪格预警 |
| 关卡 | `levelTimeoutSeconds` | 单局限时（0 = 不限时） |
| 奖励 | `rewardCoinsBase` / `rewardCoinsPerLevel` | 金币 = base + perLevel × 关卡 |
| | `rewardEpBase` / `rewardEpPerLevel` | 经验 = base + perLevel × 关卡 |
| 开关 | `multiSelfDamage` | `true/false`：多人里自己的炸弹是否炸自己 |

## 7. 玩家怎么开关模组

玩家的启用状态**不写回你的 `mod.json`**，而是存在 `Data/settings.ini`：

```ini
[mods]
enabled=my_first_mod,another_mod
allowNative=false
```

所以你更新模组、改 `enabledByDefault` 都不会覆盖玩家的选择。
玩家在「主页 → 模组」里勾选/取消，**立刻生效**（关卡、道具、界面外观会一起重载），
不需要重启游戏。

**唯一的例外是原生模组**：DLL 一旦加载就不能卸载，所以它的开关要**重启游戏**才生效 ——
模组页会明确这么提示（而不是假装立刻生效）。

## 8. 出问题怎么查

- 游戏里「主页 → 模组」：列表里灰色的就是没能生效的，选中会显示原因，摘要行会告诉你有几个有问题；
- `logs/game.log` 里的 `[mod]`、`[launch]` 与 `[theme]` 开头的行：加载顺序、覆盖条数、未知键、
  令牌问题、崩溃保护判定都记在这里；
- 最常见的四种原因：`apiVersion` 没写、声明了未开放的能力、JSON 里有多余的逗号导致解析失败、
  原生模组没有打开「允许原生模组」。

## 9. 原生模组（C ABI，`features: ["hooks"]`）

原生模组 = 一个 DLL。它能做的事远超数据覆盖：订阅引擎事件、只读查询世界、请求暂停、
触发已有道具的效果，并且**能够完全接管进程**。

**它和别的模组最大的区别是"崩了会带走整个游戏"**，所以：

- 默认**关闭**，玩家必须在「设置」里打开「允许原生模组」；
- 勾选开关要**重启游戏**才生效；
- 崩溃保护会自动兜底（见 9.5）。

### 9.1 目录形态

```
mods/my_native_mod/
├── mod.json          # 见 9.2
├── my_native_mod.dll # 与目录同名（不同名时用 mod.json 的 nativeLib 指定）
├── config/…          # 可选：数据覆盖，和普通模组完全一样
└── ui/…              # 可选：界面覆盖，同上
```

### 9.2 `mod.json`

```json
{
  "id": "my_native_mod",
  "name": "我的原生模组",
  "version": "1.0",
  "apiVersion": "0.1.1",
  "native": true,
  "features": ["hooks"]
}
```

### 9.3 写一个最小模组

头文件是 `sdk/bp_mod_api.h`（**纯 C**：C/C++ 直接 include，Rust/Zig 用 bindgen/@cImport，
C# 用 `DllImport`，Python 用 `ctypes`）。唯一要导出的符号是 `bp_mod_entry`。

```cpp
#include "bp_mod_api.h"
#include <cstddef>
#include <cstring>

#define HAS_FN(host, fn) \
    ((host) != nullptr && (host)->size >= (uint32_t)(offsetof(BpHostApi, fn) + sizeof((host)->fn)))

static const BpHostApi* g_host = nullptr;

static void BP_CALL on_boom(const BpGameEvent* ev, void* /*user*/)
{
    const BpEventExplosion* boom = static_cast<const BpEventExplosion*>(ev->payload);
    (void)boom;                       /* row / col / range 都在这里；只在本次回调内有效 */
}

static BpResult BP_CALL mod_init(const BpModInfo* info, const BpHostApi* host)
{
    if (info->buildId != BP_BUILD_ID) { return -1; }          /* 头文件/平台不一致就拒绝 */
    if (!host->has_feature(BpStr{ "event.subscribe", -1 })) { return -2; }

    g_host = host;
    host->subscribe(BP_EVENT_BOMB_EXPLODED, on_boom, nullptr);
    return 0;
}

static void BP_CALL mod_shutdown(void) {}
static void BP_CALL mod_tick(double /*dt*/) {}

static const BpModApi g_api = {
    sizeof(BpModApi), mod_init, mod_shutdown, mod_tick,
    nullptr, nullptr, nullptr, nullptr                        /* L3 预留槽位 */
};

extern "C" BP_EXPORT const BpModApi* BP_CALL bp_mod_entry(const char* hostApiVersion,
                                                         const BpHostApi* host)
{
    if (!hostApiVersion || std::strcmp(hostApiVersion, BP_MOD_API_VERSION) != 0) { return nullptr; }
    return &g_api;
}
```

编译（示例脚本见 `sdk/samples/hello_native/build.bat`）：

```bat
cl /LD /MD /std:c++17 /utf-8 /EHsc /I..\.. my_native_mod.cpp /link /OUT:my_native_mod.dll
```

`/utf-8` 不是可选项：源码里有中文而没加它，MSVC 会按本地代码页解码，
某个汉字的字节可能吃掉字符串的结尾引号（报"字符串字面量中的换行符"）。

### 9.4 能用的能力（接口 0.1.2）

| 能力名 | 说明 |
|---|---|
| `event.subscribe` | 订阅事件（爆炸、放弹、受伤、死亡、掉落、使用道具、关卡开始/结束…） |
| `world.read` | 棋盘尺寸、某格是什么、敌人/掉落/玩家快照 |
| `world.read.bombs` | 炸弹快照：引信、威力、归属 |
| `world.read.players` | 多人模式下按 `player_state(index)` 取每个玩家 |
| `world.read.meta` | 关卡号 / 阶段 / 逻辑步 |
| `world.write.var` | 改数值（与 `config/gameplay.json` **同一张白名单**，见第 6 节） |
| `world.write.entity` | 生成/移除/伤害实体、放弹、生成掉落物 |
| `time.scale` | 时间倍率（0 = 冻结，上限 4） |
| `pause.control` | 请求暂停 |
| `item.effect` | 触发一件**已有**道具的效果 |
| `rng` | 独立随机流（**必须用它**，自己抽随机会让联机各端不同步） |
| `mode.register` | 注册一个模式（出现在「开始游戏 → 选择模式」里） |
| `mode.hooks` / `map.generator` / `ai.controller` / `win.condition` | 三个钩子：地图、敌人 AI、胜负 |

所有写请求都是**请求**：越界、写墙、超上限、游戏已结束 → 返回 `BP_ERR_REJECTED`，世界一点都没变。
**契约里最硬的一条是"绝不调了没反应"** —— 所以别假设能力存在：用 `has_feature` 判断，
并用 `host->size` 判断"这个函数指针在我这版引擎上存不存在"。

### 9.4.1 给游戏加一个新模式（这是"最开放"的那一档）

模式**不是关卡**：点卡片直接开局，关卡流程（想分几关、怎么推进）由你自己设计，
游戏不在中间插一层界面。在 `init` 里注册：

```cpp
BpModeDesc mode = {};
mode.size  = sizeof(BpModeDesc);
mode.id    = BpStr{ "my_mode", -1 };        // 本模组内唯一
mode.name  = BpStr{ "我的玩法", -1 };        // 「选择模式」里的卡片标题
mode.hint  = BpStr{ "一句话说明", -1 };      // 卡片副标题
mode.kind  = BP_MODE_KIND_HOOKS;            // 本版本只支持这一种
mode.flags = BP_MODE_FLAG_SINGLE | BP_MODE_FLAG_TAKE_OVER_MAP
           | BP_MODE_FLAG_TAKE_OVER_AI | BP_MODE_FLAG_TAKE_OVER_WIN;
host->register_mode(&mode);
```

然后实现你想接管的钩子（**全部可选**，没声明/返回 0 就交回引擎默认）：

| 钩子 | 你能决定什么 | 引擎仍然负责什么 |
|---|---|---|
| `on_generate_map` | 铺哪些格子（`set_tile`）、敌人放哪（`spawn_enemy`）、玩家出生点（`set_player_start`） | 边框永远是墙、格子范围校验 |
| `on_enemy_think` | 这个敌人这一步往哪走、要不要放弹 | 走位与碰撞（你的 AI 进不了墙）、放弹上限 |
| `on_check_win` | 这局算不算结束、谁赢、显示什么话 | 真的结束本局（走引擎的收尾流程） |

配套：`on_mode_start(id)` / `on_mode_stop(id)` 在模式开始/结束时调用
（崩溃时不会调 `on_mode_stop`，所以别把关键保存放在那里）。
模式内部的"多关流程"请自己在模组里实现（自己记阶段、用生成实体/胜负钩子推进）。

联机：`BP_MODE_FLAG_MULTIPLAYER` 表示"主机跑规则、客户端镜像"；
如果你的模式要**自己搞联机**（自己的 socket 与协议），声明 `BP_MODE_FLAG_OWN_NETWORK`，
游戏只负责在本机把它跑起来，网络完全是你的事。

### 9.4.2 用 Python 写模组（不用碰 C）

`sdk/python_shim` 编出来的 `bp_python_shim.dll` 是**通用胶水**：把它改名放进模组目录，
再放一份 `bp_mod_api.py` 和你自己的 `mod.py`，游戏就会加载它 —— 逻辑全在 Python 里：

```
mods/my_python_mod/
├── mod.json          # "native": true, "nativeLib": "my_python_mod", "apiVersion": "0.1.2"
├── my_python_mod.dll # ← bp_python_shim.dll 改名
├── bp_mod_api.py     # ← sdk/python/bp_mod_api.py 的副本
└── mod.py            # 你写的一切
```

```python
import bp_mod_api as api

HOST = None

def bp_init(host_ptr, mod_dir):
    global HOST
    HOST = api.Host(host_ptr, mod_dir)      # 校验过版本与指针宽度才会成功
    HOST.log("你好，引擎")
    HOST.register_mode("my_mode", "我的玩法", hint="Python 写的模式")
    return 0                                 # 非 0 = 我拒绝加载

def bp_on_event(event_type, row, col, amount, text):
    if event_type == api.BP_EVENT_BOMB_EXPLODED:
        HOST.log("炸了：%d %d" % (row, col))

def bp_enemy_think(enemy_id, row, col, x, y, hp, max_hp, step, dt):
    me = HOST.player_state(0)
    if me is None:
        return 0                             # 没意见 -> 引擎默认 AI
    direction = 3 if me.col > col else (2 if me.col < col else 1 if me.row > row else 0 if me.row < row else -1)
    return api.think(direction, place_bomb=(me.col == col and me.row == row))
```

运行期会在五处找 CPython（模组自带 `python/`、exe 同级、`PATH`、注册表、官方默认目录），
要求 **3.8+**。找不到就"如实失败"：模组页显示原因，游戏照常启动。
完整示例见 `sdk/samples/hello_python`，端到端验证是 `sdk/python/shim_check.py`。

完整可运行的例子还有 `sdk/samples/hello_native`（C++，含一个真模式），
跨语言验证脚本是 `sdk/python/abi_check.py`（Python 当宿主，55 项检查）。规则细节见
`sdk/bp_mod_api.h`（**头注释就是契约**）。

### 9.5 游戏打不开了怎么办（安全模式）

原生模组崩了会把游戏一起带走。为此游戏有一条专门的恢复路径：

| 情况 | 下一次启动的行为 |
|---|---|
| 上次正常退出，或上次成功进过主页 | 正常加载 |
| 上次异常结束（第 1 次） | **照常加载**，但弹一次提示，让你选：用安全模式启动 / 禁用这些模组 / 仍然正常启动 |
| 连续 2 次异常结束 | **自动进入安全模式**：本次一个原生模组都不加载 |
| 想手动排除 | 启动时**按住 Shift**，或加参数 `--safe-mode` |

安全模式下窗口顶部有一条"安全模式：原生模组已全部禁用"的横幅，模组页会把原生模组
标成"因崩溃保护被跳过"，你可以逐个勾选启用（重启后生效）。
**安全模式只对本次运行有效**，不会写进设置 —— 所以重启一次就恢复正常加载。

出问题时 `logs/game.log` 里的 `[launch]` 行会告诉你：崩溃发生在**加载哪个模组**的时候
（那份记录写在 `Data/launch_state.json` 里，即使游戏来不及写日志也已经落盘）。
